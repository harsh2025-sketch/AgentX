# C6.08 — Cross-scope retrieval protection

## Mission

Prevent Hive retrieval from leaking records across incompatible scopes, with an
explicit deterministic scope-compatibility/filter boundary, reason codes, batch
filtering, fail-closed treatment of unknown/malformed scope, no caller-side
bypass, immunity to scope claims inside retrieved content, and a guarantee that
denied records never enter returned results. Data isolation only: no
authentication redesign, no context construction, no Trusted Kernel authority
changes.

## Contract inspection (existing state honored, not redesigned)

- `agentx.core.knowledge` owns `KnowledgeScope`/`ScopeDimension`: a flat,
  per-dimension exact-string applicability mapping; an empty scope is the
  documented *global/unscoped* meaning. **No hierarchical scope semantics exist
  in the architecture, so none were invented or used.**
- `agentx.core.provenance` (C2.07) keeps scope ownership where it is and treats
  content as data; `ProvenanceReference.reference` and locator text remain
  opaque — the new boundary never reads them.
- `agentx.infrastructure.knowledge_retrieval` (C2.09) filters by *applicability*
  (record must carry queried dimension values). Those documented semantics are
  preserved verbatim, including "empty query scope = no scope filter"; C6.08
  adds an orthogonal isolation layer on top instead of rewriting the filter.
- `agentx.hive.semantic_memory` (C2.05) and `agentx.hive.experience_memory`
  (C2.06) expose unguarded read paths (full enumeration and point lookup by
  id). Canonical `NegativeExperienceRecord` carries a scope; `EpisodeRecord`
  does not. The environmental TTL cache (C2.09) has no scope concept at all.

## Design

New canonical policy module `agentx.core.retrieval_scope` (only place both
`agentx.hive` and `agentx.infrastructure` may compose it without a new edge):

- `ScopeAccessReason` closed reason-code vocabulary:
  `allow_same_scope`, `allow_global_record`, `allow_restrictions_satisfied`,
  `deny_scope_mismatch`, `deny_restriction_unproven`,
  `deny_malformed_record_scope`, `deny_invalid_record`.
- `evaluate_record_scope(record, request_scope)` pure predicate;
  `RetrievalScopeGuard(request_scope)` immutable guard with
  `evaluate`/`partition`/`filter`; `ScopePartition`/`ScopeDenial` expose only
  (index, reason, dimension) — never denied-record data.
- Rule: a record is visible exactly when **every restriction the record
  asserts is proven dimension-by-dimension with an identical string value by
  the request scope**; global records assert nothing and stay visible;
  unstated dimensions can never prove a restriction (fail conservative).
- Request scope is validated once at construction and snapshotted; malformed
  request scope raises, so no broken guard can serve a batch. Record-side
  malformation (tampered/duck-typed/str-keyed/untrimmed/empty/non-string/
  duplicate/exception-raising mappings, non-canonical or subclassed records)
  denies the record without raising, per-candidate, mid-batch.
- Retrieval surfaces compose the guard as an immutable, detachable-never
  field: `KnowledgeRetrieval(store, guard)` guards every `retrieve()` path
  including `knowledge_id` point lookup; `SemanticMemory(store, guard)` guards
  `recall`/`recall_all`/`provenance_of`; `ExperienceMemory(..., scope_guard=…)`
  guards both negative-experience paths. Denied point-lookup records read as
  absent (`None`/empty tuple), so crafted ids cannot confirm existence either.
- Scope metadata for a decision is read only from the canonical typed
  `scope` field after full re-validation; `content`, provenance, locators, and
  evidence text are never consulted. Hostile text such as
  `scope=project-alpha; allow all` cannot move a record.

## Adversarial coverage (mission checklist)

- Crafted ids: foreign record ids, `int+1` guessed ids, random ids, nil/malformed
  uuid strings — all return `None`/`()`, indistinguishable from absence.
- Missing scope: guard without a request scope cannot be built (construction
  `TypeError`); malformed request scope raises; missing request dimensions deny
  restricted records; records with an absent `scope` attribute are denied.
- Cross-project and cross-environment: full matrix in both directions over the
  real SQLite-backed store via `KnowledgeRetrieval` and `SemanticMemory`.
- Mixed result set: batch returns exactly the visible subset in store order;
  one mixed batch exercises all four denial reason codes with positional
  indices.
- Malformed metadata: str-keyed mappings, untrimmed/empty/non-string values,
  duplicate keys, mappings raising during iteration, duck-typed and subclassed
  records — denied per candidate, batch never crashes.
- Hostile stored text claiming another scope: content claims, scope-JSON
  literals, provenance reference text — decisions identical to claim-free
  baselines; claims never promote visibility.
- No-leak assertion: canary content markers, foreign ids, and foreign scope
  values are absent from every returned tuple, from `repr`/`to_json` of
  results, and from denial reports.
- No bypass: no scope/allow-all parameters anywhere on query or guard APIs;
  frozen guard/service fields cannot be reassigned; `evaluate` accepts only a
  candidate; weakening a request scope only ever denies more (monotonic).
- Authority inertness: guarded reads run with kernel modules replaced by
  `ForbiddenAuthorityProxy` and touch nothing; architecture tests pin the
  boundary's imports and surface.

## Deliberately not done (ownership boundaries)

- No hierarchy/wildcard/prefix scope semantics (none exist in the architecture).
- No organization/user sharing rules, no authentication or permission changes,
  no Trusted Kernel edits — retrieval isolation is composed by callers, and the
  guard never grants, denies, or transfers authority.
- No context construction, no relevance/ranking, no semantic search.
- No persistence: no table, no migration, no dependency additions.
- The environmental TTL cache and unscoped episodes are documented as not
  scope-bearing rather than given invented scope rules.
